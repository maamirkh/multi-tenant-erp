## Prompt

A 48-section governing correction brief titled "Epic 11 — Reports & Analytics: Final `tasks.md` Structural Correction Pass Before Implementation" was provided, identifying genuine task-graph defects in the previously-generated `specs/011-reports-analytics/tasks.md` and requiring them corrected before implementation could begin. The brief's core findings and requirements, in full:

1. **Phase 0 forward dependency**: `BaseReportResult` was defined depending on `ReportEnvelopeMeta`, which was defined later in the same phase. Required fix: reorder so common contracts (period/freshness/comparison/drill-down/`ReportEnvelopeMeta`) precede the base result hierarchy.
2. **Saved-view `load()` forward dependency**: defined in Phase 1 but functionally dependent on Phase 3's `_authorize_and_validate()`, with the prior file's Gate 1 treating it as passable anyway ("pending Phase 3 but not a gate failure" — explicitly forbidden language). Required fix: split cleanly — Phase 1 delivers only independently-complete persistence (`save()`/`delete()`/list/create, `save()` validated against a registry that may be empty of real data but whose validation *mechanism* is fully real and testable via a fixture); the public `GET /saved-views/{id}` endpoint and full re-validation move entirely to Phase 3, after `_authorize_and_validate()` exists.
3. **Installments execution-integration tasks lived in Phase 2** despite depending on the Phase-3 execution service (continuity-gate wiring, Case A/B API test). Required fix: move to Phase 3; Phase 2's Installments sub-phase keeps only the adapter, the continuity-gate *service* itself (pure, independently testable), its allow-list unit test, registry, and adapter-level tests.
4. **Every Phase 2 domain "equivalence" test called the not-yet-existing Epic 11 HTTP endpoint** (e.g. `GET /reports/accounting.trial_balance`), and the GL cursor-continuity test paginated through `GET /reports/accounting.gl` before that route existed. Required fix: Phase 2 equivalence tests compare the authoritative domain service directly against the adapter's `run()` output (no HTTP); HTTP-level cross-checks and the online GL cursor-continuity test move to Phase 3.
5. **Registry count claimed "45 NOW + 3 DEFERRED" at the end of Phase 2**, but `exec.dashboard`/`crossmodule.customer_360` (2 of the 45) aren't implemented until Phases 4/5. Required fix: truthful progression — 43 at end of Phase 2, 44 after Dashboard, 45 after Customer 360; no `NOW`-status placeholder registered before its real implementation exists.
6. **`execute()` was defined before `ADAPTER_REGISTRY`**, a genuine forward dependency. Required fix: `ADAPTER_REGISTRY` construction precedes `execute()`.
7. **Exception count said "nine" but the list contained ten.** Required fix: use "ten" consistently.
8. **Phase heading/range inconsistencies**, and the document said "11 implementation phases" while phases were numbered 0 through 11 (12 phases). Required fix: consistent "12 implementation phases (Phase 0 through Phase 11)" wording and accurate ranges throughout.
9. **Export boundedness conflated a date-range filter with a row-count bound** — several Purchase/Inventory/Accounting "full-fetch-then-guard" tasks assumed a 90/366-day filter was itself a size bound, which it is not for a high-volume tenant. Required fix: classify every exportable report into exactly one of four categories (A: cheap SQL-level count exists; B: no count but genuinely capped by a real business dimension — never an unbounded date range; C: genuinely unbounded — receives a new, small, additive source-domain pagination/count seam rather than being fetched wholesale merely to discover it's too large; D: aggregate/fixed-shape, no row concept), with GL specifically using a precise "iterate cursor, stop the instant `limit+1` is observed, never scan further" strategy rather than an open-ended "abort sometime."

11. **Dashboard `WidgetState` was defined as `PRESENT | OMITTED` in one task and silently mutated to add `UNAVAILABLE` in a later task**, and two later tasks contradicted each other on whether an unexpected infrastructure error should propagate as 5xx or be silently converted to a widget state. Required fix: define the three-value state model once, with one non-contradictory rule — `UNAVAILABLE` only for a specific, typed, expected exception class; every other exception propagates as a genuine 5xx, never caught by a broad `except Exception:`.
